## Agreed boundaries and remaining proof

Current acceptance evidence: profile-bound remote authorization, the two-barrier publication transaction, HTTPS/SSH publication classes, pinned upstream provenance, native secure-store/signing-agent smoke tests, typed GitHub contributor flows, per-profile merge policy, online commit `Verified`, and audited signed-tag release are validated as recorded in `plan.md`. PR checkout withholds GH_TOKEN from Git children/hooks and verifies the fetched head against API metadata. Full locked Cargo tests, Clippy, and fmt pass on macOS arm64 and Linux arm64/x86_64. All five Darwin Nix checks pass; Linux arm64/x86_64 Nix flake checks pass in disposable VMs with `--option filter-syscalls false` while retaining the default Nix build sandbox. This works around OrbStack's seccomp BPF restriction without changing project Nix configuration. The final independent acceptance reviewer confirmed this matrix and the approved sequence with no findings; all approved gates are closed. No provider or real credential was used.

- Persona mediates only its managed paths. Direct native executables, aliases, other network tools, and hostile same-user processes can bypass it; this is not a sandbox or anonymity system.
- No provider or real credential was used in the probes above. Future integration tests must remain local and synthetic.
- Required evidence that is absent, ambiguous, stale, unbounded, or not observed is `UNKNOWN`/blocked, never `PASS`.
- Cargo and Nix checks are validated on macOS arm64, Linux arm64, and Linux x86_64. Linux Nix runs require `filter-syscalls=false` in OrbStack; the Nix build sandbox stays enabled. This is an invocation workaround only, not a project flake change.
- Full-completion target selected: contributor and maintainer workflows including ordinary Git defaults, fork/upstream roles, branch/tag/multi-ref/deletion/exact-lease publication, explicit upstream provenance, PR checkout/create/review/merge, native GitHub CLI account/headless coverage, managed release creation from an already-published, audited tag (never an implicit tag push), opt-in online GitHub `Verified` observations, and Cargo/Nix support for macOS arm64 and Linux arm64/x86_64.
- User decisions: finish this full target before personal onboarding; commands outside configured scopes remain blocked; commits ancestral to an explicitly approved pinned upstream OID may retain upstream authors, committers, and signatures, while new commits follow Persona policy and cherry-pick author preservation remains explicit.
- GitHub server-side PR merge uses a distinct, explicit profile policy (account, repository, target branch, strategy). It does not authorize commits created locally and does not claim that server-created merge commits bear the user's local signing-key signature. Auto-merge, merge queues, administrative bypass, and branch deletion are not implicitly included.
- Current-source locked all-target Cargo tests, Clippy, and fmt pass on all three targets; native-store smoke evidence and transport fixtures are documented above. The final independent acceptance review returned OK; all approved gates are closed.
- Release creation is not atomic with tag publication; Persona must not create or push the tag implicitly, must verify the remote/local tag object before and after release creation, and must report races or ambiguous partial success without destructive rollback.
- Explicitly unsupported boundaries: direct native-binary use is a documented mediation bypass (not a sandbox); protocols/helpers outside the allowlisted grammar, force without exact lease, provider endpoints/extensions outside GitHub.com and arbitrary REST are not accepted.
- Final status must enumerate exact supported command forms and the tests for each. A skip, partial scan, historical gate result, or package build does not establish an untested integration.
