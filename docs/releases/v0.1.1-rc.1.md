# Persona v0.1.1-rc.1

This patch release candidate includes a compatibility fix for managed HTTPS Git credential-helper requests. It remains a release candidate, not a security boundary or a claim of production readiness.

## Changes

- Accept Git's repeated capability and WWW-authentication metadata while parsing only the unique HTTPS protocol, host and repository path used for authorization.
- Accept newline, CRLF and EOF-terminated credential-protocol input. Reject duplicate destination fields, caller-supplied credential material, URL overrides and non-HTTPS requests.
- Forward only the resolved absolute `gh` executable path to the managed Git child; do not restore the caller's `PATH` or `HOME`.
- Add parser, synthetic CLI, native `git credential fill`, and direct installed-shim regression coverage.

## Validation

- `just check` passed on macOS arm64, including locked all-target tests, formatting, Clippy, Rust 1.85 compatibility, and documentation tests.
- `nix flake check` passed on macOS arm64, including build, test, Clippy, format, and installed-smoke checks.
- Hosted CI on Linux x86_64, Linux arm64, and macOS arm64 for the exact candidate commit is required before publishing.
- Synthetic credential tests exercise the native Git credential-fill flow; no real GitHub push is exercised.

## Limitations

Persona mediates only documented managed paths; direct native binaries and hostile same-user processes remain outside its boundary. Unsupported operations fail closed. See the [security model](../security-model.md), [troubleshooting guide](../troubleshooting.md), and [release procedure](../releasing.md).
