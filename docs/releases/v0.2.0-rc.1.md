# Persona v0.2.0-rc.1

This release candidate refactors Persona around strict cross-identity guardrails and configurable allowlist/denylist command policies so day-to-day Git, GitHub CLI, and wrapped tool workflows run smoothly without weakening identity, signing, destination, or credential separation. It is not a stable release or a production security boundary.

## Changes since v0.1.1-rc.3

- **Configurable command policies (`denylist` / `allowlist`)**: Added `CommandPolicy` (`mode = "denylist"` default, `"allowlist"` supported cleanly and preserved for legacy `allow = [...]` configurations) across `[profiles.git.commands]`, `[profiles.github.commands]`, and `[profiles.run]`. Rules support command selectors, parent-child prefixes (`fetch` matches `fetch.all`), wildcards (`tag.*`), and flag-specific rules (`push --force`), with `deny` always taking precedence over `allow`. Added `persona profile commands <PROFILE>` and updated `persona profile add|update|show`.
- **Day-to-day Git and `gh` workflow compatibility**: Permitted everyday Git operations (`log`, `diff`, `show`, `stash`, `branch`, `tag`, `merge`, `rebase`, non-atomic multi-ref pushes, tag creation without boilerplate zero-OID `--force-with-lease`) and `gh` operations (with automatic `OWNER/REPO` inference from `origin` inside a Git checkout) while keeping strict author/committer injection, signing enforcement, destination/SSH/token isolation, and typed `pr checkout`/`pr review`/`pr merge`/`release create`/`release upload` gates.
- **Wildcard boundaries & explicit deny rules**: Supported trailing owner/prefix wildcards (`OWNER/*`, `https://github.com/OWNER/*`, `git@github.com:OWNER/*`, `*`) alongside explicit `deny_destinations` and `deny_repositories` overrides across push/fetch audit, HTTPS credential helper, `gh`, and SSH checks.
- **Cross-profile leak detection & upstream provenance modes**: Added `cross_profile_identity_check` (default `true`) to block unpublished outgoing commits carrying another configured Persona profile's author or committer identity even when `preserve_authors = true`. Defaulted `upstream_provenance` to `"remote_tracking"` (unless `upstream_baselines` is populated, which keeps `"pinned"`), added `persona baseline update [--preview]`, and gated local hooks/filters/merge drivers behind opt-in `strict_repo_hooks`, `strict_git_filters`, and `strict_merge_drivers` flags (default `false`) so developer hooks and Git LFS filters work out of the box.
- **Hook lifecycle improvements**: Added `persona hooks refresh [--preview]` and `hooks-registry.json` tracking so `persona install refresh --apply` automatically refreshes registered repository `pre-push` hooks after Persona upgrades.
- **Modularized adapters**: Extracted managed runtime helpers, Git adapter, GitHub runner, SSH adapter, pre-push handler, destination matching, and command policy evaluation out of `src/main.rs` into dedicated library modules.

## Validation

- Local checks (`just check`, `cargo build --locked --release`, and macOS `nix flake check`) verify formatting, Rust 1.85 MSRV compatibility, Clippy (`-D warnings`), documentation links/examples, and locked synthetic tests across all suites.
- Before tagging, hosted CI must pass on Linux x86_64, Linux arm64, and macOS arm64 for the exact final commit. Publish the final commit/run/asset verification evidence in the GitHub prerelease record.

## Limitations

Persona mediates only managed PATH shims, `persona run`, and installed `pre-push` hooks; direct native executables (e.g., `/usr/bin/git`), `--no-verify`, and same-user processes remain outside its boundary. Command allow/deny lists never relax identity, signing, destination, or credential separation invariants. Production security use has not been evaluated. See the [configuration guide](../configuration.md), [managed commands](../managed-commands.md), [security model](../security-model.md), and [release procedure](../releasing.md).
