# Persona v0.1.0-rc.1

This is the historical record for Persona's first private release candidate. The repository was private at the time. This note records evidence and limitations at that release cut; later CI results and the subsequent limited local pilot are tracked in the [current evidence matrix](../implementation-matrix.md).

Persona is a directory-scoped Git identity guardrail with bounded managed Git/GitHub CLI paths. It is not a sandbox, network isolation layer, or universal Git/GitHub replacement. Direct native binaries and hostile same-user processes remain outside the mediation boundary.

## Included at the release cut

- Canonical configuration v3 and conservative v1/v2 migration.
- Typed managed Git/GitHub operations, signing verification, pinned upstream provenance, and bounded publication checks.
- Explicit installation/refresh/removal/rollback and Nix packages/checks for the declared macOS/Linux architectures.

## Validation recorded at the release cut

The workflow was configured for Linux x86_64, Linux arm64, and macOS arm64. The latest manual dispatch then available (`648d8a62f69030590a33e45eed2bcdd08857f819`) ended with `startup_failure` before jobs or check runs were created; no hosted CI result was claimed at that time.

Local validation included locked all-target Cargo tests, formatting, Clippy with warnings denied, and Rust 1.85 compatibility on macOS arm64; locked all-target Cargo tests and Clippy on Linux x86_64 and arm64; and Nix build, test, Clippy, format, and installed-smoke checks on the declared targets. OrbStack Linux Nix validation used `filter-syscalls=false` while retaining the Nix build sandbox. The sandbox skipped loopback HTTPS and local SSH-server authentication fixtures; those transport tests passed in native Linux Cargo suites.

Automated GitHub/account/credential integration tests used synthetic identities and local fixtures. GitHub authorization was separately used for repository administration and release artifacts; no live credential was included in source or release assets. No real Persona provider onboarding had been exercised at this release cut.

## Limitations recorded at the release cut

- Persona mediates only its documented managed paths. Direct native binaries, other network tools, and hostile same-user processes can bypass it.
- Unsupported Git forms, providers, enterprise hosts, and arbitrary GitHub API requests fail closed.
- Release creation cannot atomically bind GitHub's tag name to a tag-object OID. Persona verifies the remote tag before and after the API call, but a concurrent retag/deletion race is detectable only afterward. The release path never creates or pushes the tag.
- Treat this as a release candidate, not a production security boundary.

The repository and its Nix source reference were private at this release cut; access-specific token instructions are intentionally not reproduced here. For a future public tag, use the current [installation guide](../installation.md), after its release gates are verified.
