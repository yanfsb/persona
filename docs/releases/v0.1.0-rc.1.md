# Persona v0.1.0-rc.1

This is the first private release candidate of Persona, a directory-scoped Git identity guardrail. It packages the approved, documented bounded command surface for macOS arm64 and Linux arm64/x86_64. This is not a sandbox, network isolation layer, or universal drop-in replacement for Git/GitHub CLI.

## Included

- Canonical configuration v3, with conservative v1/v2 migration and explicit per-profile remote and GitHub merge policy.
- Typed managed Git/GitHub operations; signed commit/tag verification; pinned upstream provenance; bounded exact-object history audit.
- Two-barrier authenticated publication plans with exact lease/ref checks over managed HTTPS and SSH.
- Profile-bound GitHub account selection, PR checkout/review/merge, explicit online commit `Verified` checks, and release creation from an already published, locally audited signed annotated tag.
- Explicit install/refresh/remove/rollback and Nix packages/checks for Darwin arm64 and both Linux architectures.

The sandbox skips loopback HTTPS and local SSH-server authentication fixtures; those transport tests ran in the native Linux Cargo suites.

Automated GitHub/account/credential integration tests use synthetic identities and local fixtures only. The maintainer's GitHub account was used separately to create the private repository and publish this release; no live credential is included in the source tree or release assets.

## Important limitations

- Persona mediates only its documented managed paths. Direct native binaries, other network tools, and hostile same-user processes can bypass it.
- Unsupported Git forms, providers, enterprise hosts, and arbitrary GitHub API requests fail closed.
- Release creation cannot atomically bind GitHub's tag name to a tag-object OID. Persona verifies the remote tag before and after the API call, but a concurrent retag/deletion race is only detectable afterward. The release path never creates or pushes the tag.
- No real-provider onboarding has been exercised. Treat this as a release candidate and perform a controlled pilot before relying on it for production publishing.

## Source and Nix

The repository is private. Fetch it with an authorized GitHub API token supplied ephemerally via Nix's `access-tokens` setting (for example from an existing `gh auth token` session); never embed a token in Nix source or the lock file. The lock pins the resolved revision and NAR hash. This release ships source archives and checksums, not prebuilt binary archives or a binary cache.
