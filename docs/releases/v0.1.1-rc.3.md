# Persona v0.1.1-rc.3

This follow-up release candidate completes the documented managed source-release workflow and hardens synthetic transport fixtures. It is not a stable release or a production security boundary.

## Changes since RC2

- Add bounded `persona run -- gh release upload TAG FILE... --repo OWNER/REPO` for an existing release. Upload requires the enrolled account, explicit repository and publication destination, locally verified signed annotated tag, and matching remote tag before and after the operation.
- Snapshot one to eight regular files within the physical managed worktree before credential selection or network calls. No-follow descriptor-relative opens reject symlink escapes and replacement races. Limits are 64 MiB per file and 128 MiB total.
- Upload snapshotted bytes through curl 8.3+ to the fixed HTTPS GitHub upload endpoint with curl configuration/proxies disabled and redirects rejected. Tokens remain out of argv. Validate returned asset metadata and supplied digests; encode asset names as query data.
- Refuse existing asset names and overwrite/deletion options. Sequential uploads report confirmed and uncertain outcomes without automatic retries or cleanup.
- Include curl in Nix runtime tools and verify its availability through the installed package's managed launcher. CI prints full Nix build logs. Synthetic upload helpers use absolute test-tool paths, with an empty-PATH regression so Linux Nix does not depend on host executable search paths.
- Start mixed-remote TLS observation after repository preparation, restore blocking reads on accepted sockets, and exercise the shared observer with a delayed ClientHello. Unconditional mixed-remote preflight tests prove zero fetch invocations without depending on local TLS support.
- Include the post-RC2 negative signing regression: a new unsigned commit still fails even when an exact pinned upstream baseline exists. Preserve Nix's existing explicit TLS fixture limitation without widening skips.

## Inherited functionality

RC2 already contains managed Git command allow/deny policy, bounded GUI-compatible defaults/refspecs, fully preflighted fetch-all, direction-specific HTTPS credential authorization, and the pinned-baseline signing fix. RC3 preserves that commit history and those protections; it does not reintroduce or relax them. Existing release tags and historical notes are unchanged.

## Validation

- `just check` passed locally: formatting, locked all-target tests, Clippy with warnings denied, Rust 1.85 all-target check, and documentation tests.
- Locked release build and all five native macOS arm64 Nix checks passed locally, including installed-package smoke checks.
- Synthetic tests cover file limits/confinement, immutable snapshots, account/repository/destination/tag denials, existing-name conflicts, malformed responses, partial outcomes, concurrent retagging, actual local curl redirect rejection, and installed-shim behavior. Independent review findings were fixed and re-reviewed.
- Before tagging, hosted CI must pass on Linux x86_64, Linux arm64, and macOS arm64 for the exact final commit. The published prerelease record must identify that commit/run and the actual asset/checksum and installation verification results; local results and earlier runs are not substitutes.

## Limitations

Uploads are not transactional and a failed request may leave an asset, including an empty starter asset. Inspect the release before retrying missing assets; no managed replacement/deletion command is provided. Pre/post tag checks detect retagging only afterward. Missing/older curl fails closed. Review asset contents separately: a worktree file is not automatically safe to disclose. Tests use synthetic identities and local services; production use has not been evaluated. See the [managed command contract](../managed-commands.md#release-asset-upload), [security model](../security-model.md), and [release procedure](../releasing.md).
